# Firefox

Installs Firefox with a managed dark theme policy, blocked conflicting synchronized themes, and generated `userChrome.css` / `userContent.css` fallbacks. It consumes `user.appearance` (required) and contributes the `firefox` Noctalia integration ID. `default.nix` and `resources/` are private implementation; `checks.nix` publicly exports the `firefox-ui` fixture check.

The Arc / Zen inspired layout uses Firefox's native `sidebar.revamp` and vertical tabs, without moving the URL field or injecting browser JavaScript. Sidebar and toolbar share the One Dark browser surface; pinned tabs have a small gray “固定标签” heading and groups use gray 12px titles. Tab labels, secondary labels, new-tab labels and the all-tabs list use Inter 14px with Noto Sans CJK SC fallback. Rows are 32px high with consistent horizontal padding, including grouped tabs. Unselected rows and their label/content containers are transparent; hover adds a 5% neutral tint. Long titles use an ellipsis. Selection has a pale fill and a 2px left blue indicator, without a second outline. Web content meets the browser edge with no rounded card or Islands frame. Websites retain their own colors; userContent rules only affect `about:home` and `about:newtab`.

The top navigation is a single 40px logical row in locked Firefox 159 (output scale 1.5). The address field retains Maple Mono NF CN 14px for distinguishable URL punctuation; its focused border and suggestion surface use the shared palette. New profiles receive back/forward/reload, URL, downloads, extensions and sidebar controls plus Firefox's native menu. Downloads remains native and can auto-hide while idle. Existing customized toolbar placements are preserved; use Firefox's Customize Toolbar to add **Sidebar** or **Reload** if absent. Firefox 159's experimental Nova layout is disabled as a default to avoid its content frame; an existing user choice wins.

**Ctrl+Alt+Z** (Firefox's native Linux `toggleSidebarKb`) or the **Sidebar** toolbar button toggles expanded tabs and the icon rail. The default expanded width is 232px; Firefox's native `customWidth` overrides that default after a user drag. The collapsed rail is 44px in the checked normal-density configuration. Firefox owns saved sidebar width, visibility and expanded state, including the existing user's hover behavior. The seed no longer forces `sidebar.visibility` or `sidebar.backupState` at every launch. Native group indicators remain available in the icon rail. Pinned tabs use a compact grid of 36px cells with transparent idle backgrounds and a pale selected fill; a faint full-width separator divides pins from the remaining tabs. The grid host follows the number of pins up to six columns and wraps within a narrower user-resized sidebar. This uses native grid variables and host CSS because the internal items-wrapper part cannot be overridden by the user stylesheet in locked Firefox 159. Bottom tool buttons inherit the same neutral icon fill and native uniform spacing. No extension or custom script implements the toggle.

The feature owns the Firefox package/policies, `about` and unknown URL handlers, and `seedFirefoxProfileUi` activation. The activation and Noctalia hook split one palette template into separate marker blocks in `chrome/userChrome.css` and `chrome/userContent.css`. Only activation maintains the `user.js` marker block. Styles outside the markers are retained byte for byte. Missing markers cause a block to be appended; incomplete, reversed or duplicate markers and symlinked target files/directories are refused. The hook only changes CSS and never resets preferences.

Preferences are defaults, not locks: explicit `user_pref` entries outside the managed `user.js` block win. Existing `prefs.js` choices are not adopted, and a Firefox setting changed from the previous managed value is released from the block on the next activation. `prefs.js` itself is never written. This also preserves an existing toolbar layout. An unchanged old managed default can migrate to a newer default. Startup preferences retain search, one row of up to eight frequent sites, and hide sponsored/story content; Firefox uses the xdg-desktop-portal file picker.

Firefox 159 seeds `media.hardware-video-decoding.enabled=true`, `widget.dmabuf.enabled=true` and `widget.dmabuf-webgl.enabled=true` inside that same managed marker. Mozilla defines all three with `true` defaults; the legacy `media.ffmpeg.vaapi.enabled` is no longer defined in Firefox 159, so it is not seeded. `media.hardware-video-decoding.force-enabled` and `widget.dmabuf.force-enabled` stay `false` so Firefox can honor its driver and codec blocklists. The selected Legion host supplies Intel's iHD VA-API driver, but only `about:support` and active-playback logs can prove a particular codec uses the iGPU. Check `about:support` → Graphics → Decision Log / Codec Support and play a known supported stream; on a diagnostic launch, `MOZ_LOG=FFmpegVideo:5` logs VA-API decoder selection. `intel_gpu_top` should show Video activity on the Intel render engine during playback. These runtime checks remain outstanding for the installed generation.

Dark Reader is no longer force-installed: forced automatic recoloring conflicts with preserving website colors. This does not uninstall or reset an existing user's extension. If Dark Reader was installed by an older generation and still recolors pages, disable it or opt individual sites out in its own UI after upgrading. The feature does not edit extension storage, accounts, bookmarks, history, credentials or session state.

Removing the feature removes its package, policies, URL handler and activation. Seeded preferences and marked stylesheets remain in the profile; profile data is never deleted. To revert the UI, remove only the repository marker blocks after closing Firefox, and use native Settings/Customize for preferences the user has since changed.

`resources/test_firefox_ui.py FALLBACK_CSS` parses both stylesheets and exercises seeding, old-generation preference migration, user overrides (including hardware-decoding preferences), idempotence and the Noctalia hook against temporary profiles. The public check obtains the exact fallback from Home Manager activation data, renders the template using the actual offline Noctalia engine and compares it with the fallback. Custom colors use `onedark_*_value` for exact values; unsuffixed roles are Material tonal derivatives even with `blend=false`.

Visual verification for r43 used real Firefox 159 in private headless Sway at 2560×1600 / scale 1.5, synthetic pages and private HOME/XDG/D-Bus. Multi-tab Chinese titles, two pins, native groups, keyboard collapse/expand, focused URL, downloads, location permission and narrow-window behavior are checked independently of Nix evaluation/build. The production profile and portal backend still require host verification after integration; no rebuild or activation is performed by this batch.

Firefox's new-tab search handoff placeholder has native shadow-tree opacity (0.54 in the previously measured Firefox 158). Public host color tokens do not control that opacity; the palette's text contrast does not certify the native placeholder.
