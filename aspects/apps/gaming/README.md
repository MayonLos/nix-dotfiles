# Gaming

Configures gaming tools for a selected user and routes shared NixOS support through `gaming-host`. The host side owns Steam, Gamescope and GameMode integration; the user side configures MangoHud and Prism Launcher. The user's GameMode group membership is part of this feature.

Outputs include Steam and host gaming support, MangoHud metrics, and Prism Launcher with the selected Java toolchains, FFmpeg, MangoHud, Gamescope, and GameMode support. When the user has an appearance palette, it installs Prism's One Dark theme from the public `desktop/session-support.qt-style.nix` factory plus a Prism-only stylesheet. Main-window top and instance action toolbuttons have transparent default surfaces, with a quiet border on hover and a blue border for pressed, checked, or focused states. Prism settings tabs use a clear blue underline, nested group boxes lose duplicate slabs while keeping checkable indicators visible, disabled editor fields remain readable, and dialog footer buttons use compact spacing. A native Prism cat pack supplies the low-contrast geometric prism in the instance library, and a native icon theme replaces only the top `cat` action while inheriting `pe_colored` for other icons. Select `One Dark` under Settings → Appearance → Theme, `One Dark Prism` under Icon Theme (stored ID `NixDotfilesPrism`), and `Nix Dotfiles Prism` under Cat Pack (stored ID `NixDotfilesPrism`) once. Prism owns these selection settings and account/instance state. GPU-specific GameMode device settings come from host facts in the hardware feature.

Owned files are `default.nix`, `host/`, `mangohud.nix`, `prismlauncher.nix`, `resources/prism/`, and the explicit test hook `checks.nix`; implementation Nix files are private. Removing the feature withdraws package, service, group declarations, theme, icon theme and cat pack files when activated. It preserves Steam libraries, game saves, Prism instances, downloaded mods, launcher accounts, and Prism's selected appearance settings.

## Performance and launch commands

`game-run COMMAND [ARG ...]` probes `nvidia-smi -L` with a three-second timeout at launch, sets PRIME OpenGL/Vulkan offload variables only when a GPU is available, and executes `gamemoderun`. If NVIDIA is powered off/unavailable it clears inherited offload selectors, prints a fallback notice and launches on the default Intel GPU. `GAME_RUN_GPU=integrated game-run ...` skips the probe. It issues no GPU power-switching command and does not retry a game after it has started; the NVIDIA probe can wake a runtime-suspended GPU; a GPU disappearing after the probe still needs application handling. Arguments, signals and the game's exit code pass through `exec`.

Steam's FHS environment runs the same probe once when Steam starts and supplies both GameMode library ABIs. GameMode is not preloaded session-wide: inherited `libgamemodeauto.so.0` reached every Steam helper, and a blacklisted helper (the client's websocket `lsof` check) aborted inside libdbus, so Steam failed at startup with "Unexpected Transport Error (0x3008)". Enable GameMode per game with the launch option `gamemoderun %command%`. Restart Steam after changing GPU availability; its environment is a launch-time snapshot. Existing game launch options remain application-owned.

Prism is patched at its game-launch boundary to prepend `game-run` to the existing wrapper, including instance-specific wrappers. This preserves user settings and keeps the launcher UI outside GameMode. The replacement is exact and fails a package build if upstream changes that boundary. Existing Prism GameMode/discrete-GPU switches can stay as chosen; the wrapper rechecks NVIDIA and clears stale selectors before the game starts. Accounts, instances and launcher config are never rewritten.

On GameMode's first client, `gaming-mode-hook start` saves the current PPD profile (including a manually selected one), acquires `gaming-idle-inhibit.service`, then sets `performance`. On the last client, `end` restores that saved profile and releases only its own inhibitor. Duplicate hooks are idempotent; a runtime-directory file lock serializes concurrent calls with a ten-second acquisition limit. Each child command has a fifteen-second timeout and GameMode allows 150 seconds for recovery/start/rollback. Failure rolls back both actions; a failed restore retains a retry record and still releases the inhibitor. `gaming-mode-hook end` retries recovery, and `gamemoded.service` has the same recovery as `ExecStopPost` if the daemon exits. The inhibitor has no login wants and is `PartOf=gamemoded.service`; it holds logind **idle** only, not explicit suspend or manual lock. Locked Noctalia observes logind `BlockInhibited` in its screensaver service and suppresses automatic idle actions. Existing user caffeine state is untouched. The automatic screen-off/lock integration is verified from Mango/Noctalia source; Xorg xidlehook/xss-lock behavior remains a runtime validation item. A login session must have PPD permission; a denied profile change is logged and rolled back. Hooks do not coordinate independent users changing the system-global PPD profile. A power cut or SIGKILL of the entire user manager cannot run recovery; check the profile after such an event.

The locked scx_lavd (1.1.2) loop only changes its power mode from PPD when launched with `--autopower`; the selected no-argument autopilot has no public runtime mode setter. GameMode therefore leaves lavd's load-based policy running. It does not restart scx, write BPF state or enable the previously avoided `--autopower`.

NVIDIA cache variables are `__GL_SHADER_DISK_CACHE=1`, `__GL_SHADER_DISK_CACHE_SIZE=10737418240` (10 GiB), and `__GL_SHADER_DISK_CACHE_SKIP_CLEANUP=1`; Mesa gets `MESA_SHADER_CACHE_MAX_SIZE=10G`. NVIDIA's skip-cleanup requests retaining cache entries, so 10 GiB is not a guaranteed storage cap. Driver defaults choose the cache location under the user's cache directory; no cache is cleared on activation/removal. In Steam Settings → Downloads, check **Shader Pre-Caching** (wording/placement depends on client version) and optionally background Vulkan shader processing. The repository does not edit Steam's mutable settings. `proton-ge-bin` is exposed through `programs.steam.extraCompatPackages`; choose GE-Proton under the game's Compatibility settings when needed, rather than forcing every game to use it.

## Gamescope

`gamescope-run -- COMMAND` reads the current physical mode from `wlr-randr --json`; in Mango it chooses the output under the pointer via `mmsg get cursorpos`, otherwise the first enabled output. Xorg uses `xrandr --current`. `--output DP-1` reads that output's mode without moving the nested window; `--size 2560x1600 --refresh 165` bypasses discovery. Output mode discovery is read-only and the nested compositor does not reconfigure the host display.

```sh
game-run ./game --arg
gamescope-run --render-size 1920x1200 --fsr --fps 90 -- ./game
gamescope-run --output DP-1 --fps 60 -- ./game
# Steam per-game launch option when this nested preset is wanted:
gamescope-run --render-size 1920x1200 --fsr --fps 90 -- %command%
```

The default frame cap is the current output's rounded refresh rate; the nested refresh and Gamescope frame limiter are both set to the requested cap. `--fsr` selects Gamescope FSR 1 spatial scaling; choose a lower `--render-size` to obtain upscaling. `--hdr` adds `--hdr-enabled`, `ENABLE_GAMESCOPE_WSI=1` and `DXVK_HDR=1` only as an explicit opt-in. Mango's locked source contains HDR/color-management support, but that does not prove the panel, EDID, nested Gamescope protocol and game all negotiate HDR correctly. Enable HDR on a compatible output separately and verify an HDR test image/game; no force-HDR workaround is applied. Nested Gamescope, NVIDIA fallback, refresh/VRR and HDR still require real display/game validation. This feature owns the three CLI packages, their scripts, GameMode hooks/unit and Steam launch environment in addition to the files above. It does not own Mango window rules or hardware power policy.
