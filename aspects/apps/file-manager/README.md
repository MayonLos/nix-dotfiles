# File manager

Installs Thunar and File Roller for the selected user and host support for Thunar, GVfs, and thumbnailing. It needs the normal package set; host support is routed through `file-manager-host-support`.

Outputs include the managed Thunar custom actions, terminal launcher integration, File Roller archive plugin, missing-only `~/Templates` seeds for blank text, Markdown, Python, shell, Lua, and Nix documents, volume management, GVfs, and Tumbler. Custom actions open the current directory in the configured terminal, open files in Neovim, start herdr or lazygit in a directory, set images through the current session command, copy paths or image data on the active Wayland/X11 display, paste clipboard images as new PNG files, and create symlinks from copied file URIs. Existing custom action configuration is represented declaratively by `thunar-actions.nix`.

`packages.nix` is the single package factory for the archive and volume plugins and `thunarWithPlugins`; both NixOS Thunar support and the user's Home Manager package consume that same derivation. Home Manager owns `~/.local/share/dbus-1/services/org.freedesktop.FileManager1.service`, pointing to this wrapped Thunar binary with the upstream `--gapplication-service` argument. This per-user service wins over File Roller 44.7's transitive Nautilus service candidate and keeps `org.freedesktop.FileManager1` on Thunar.

In a Noctalia session, the shared session-support GTK3 asset template styles Thunar paths, table headers, and status values with the palette monospace family, while filenames retain the sans-serif family; GTK TreeView has no per-cell CSS nodes. Selected rows keep the neutral selection surface and use a narrow blue inset marker. Noctalia remains the single writer of the generated GTK CSS.

Owned files are `default.nix`, `host.nix`, `packages.nix`, `thunar-actions.nix`, `thunar-terminal.nix`, `templates.nix`, and `checks.nix`; all Nix files are private except the registered check hook. The feature owns the single per-user FileManager1 service declaration. The activation only creates missing template files, skips a user-owned `Templates` symlink, and leaves existing templates untouched. Noctalia exposes a wallpaper-set command for Mango. The current Xorg wallpaper daemon only exposes next/rotation; its custom action can update the visible image with feh, but the daemon does not persist that choice and can later replace it. Removing the feature withdraws its packages, host services, and managed action declarations; it does not delete seeded templates or application data. An existing HM-managed file may be backed up according to the host backup policy.

The locked NixOS `programs.thunar` module has no package option. Host support registers the tailored package in system packages, D-Bus and systemd, and enables Xfconf explicitly, matching that module’s four registrations. The wrapper removes only its symlinks to the upstream wallpaper plugin: its native menu supports XFCE/GNOME and otherwise does nothing, so the session-aware UCA is the sole wallpaper action. No upstream store files are changed.
