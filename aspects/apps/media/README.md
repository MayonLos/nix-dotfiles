# Media

Installs and configures media playback, capture, image viewing, music, and editing tools. `user.appearance` supplies mpv and Swayimg colors/fonts; mpv retains its packaged color defaults when no palette is selected. Hardware decoding remains a host fact owned by the hardware feature.

Outputs include mpv with uosc/MPRIS/autoload/thumbnail scripts and Anime4K shaders, Musicfox, OBS with PipeWire/wlrobs/Vulkan capture plugins, Blender, GIMP, Kdenlive, FFmpeg, ImageMagick, and Swayimg. Swayimg is the only image viewer registered by this feature. Its locked 4.7 build reports BMP, PNM, TGA, DICOM, JPEG, PNG, GIF, WebP, SVG, HEIF (including HEIC), AVIF, JXL, EXR, TIFF, Sixel, and RAW support; its nixpkgs recipe links the matching decoder libraries. The feature registers video and image MIME handlers and publishes a visible Swayimg desktop entry.

mpv subtitles and OSD use bright text with a deep outline and monospace readouts. uosc uses neutral selection fills, bright text, an 8 px native radius, blue search matches, and a 2 px blue selected-row marker; its 2 px line timeline is kept thin. uosc exposes no glow control for the marker, so it remains a flat blue cue. A bounded uosc 5.12 theme adaptation separates selection fills from icon/progress foregrounds and adds the marker (the upstream menu highlight opacity is retained). The adaptation fails to build if the expected upstream snippets change. Swayimg uses One Dark backgrounds, persistent opaque bottom information (filename, dimensions, scale, and image index; `info_timeout=0` disables the upstream five-second timeout), and a 2 px blue gallery outline. Viewer shortcuts are Left/Right or h/l for previous/next, r/Shift+r to rotate, f to fit, 1 for original size, Delete for a Zenity confirmation followed by moving the image to Trash, Ctrl+c to copy a PNG representation of the first frame to the active Wayland/X11 clipboard, and Ctrl+g to open the file in GIMP. Shift+Delete and d are explicitly disabled in viewer and gallery; gallery deletion is also disabled, so browsing thumbnails cannot invoke the trash action. With `list.fsmon=yes`, moving the current file to Trash produces a remove event; the viewer removes it from the list and advances.

The upstream Swayimg 4.7 `exec` action substitutes `%` verbatim before invoking `$SHELL -c`. The local `swayimg-package.nix` patch adds `%q`, which quotes the path as one POSIX shell word while preserving the upstream `%` and `%%` behavior. Delete, Ctrl+c, and Ctrl+g use `%q`, including for paths containing single quotes, `$()`, backticks, and newlines. The scoped C regression check executes the patched expression with those names and confirms the metacharacters remain literal.

Owned files are `default.nix`, `blender.nix`, `images.nix`, `swayimg-package.nix`, `checks.nix`, `mpv.nix`, `musicfox.nix`, `obs-studio.nix`, `resources/swayimg-shellcmd-safe-path.patch`, and `resources/swayimg-shellcmd-check.c`; these implementation files are private to the feature except `checks.nix`, the explicitly registered public test hook. `images.nix` owns the Swayimg INI and its three scoped helper executables (confirmed trash, clipboard conversion, and detached GIMP open). Removing the feature removes package, MIME, and configuration declarations, while media libraries, OBS profiles/recordings, Blender projects, images, and other user data remain on disk. The viewer check verifies the rendered configuration and the locked binary's advertised decoder formats; the shell check compiles the locked upstream helper with the local patch and tests safe path expansion. GUI appearance and decoder runtime still require the isolated screenshot/runtime verification for this round.
