# Media

Installs and configures media playback, capture, image viewing, music, and editing tools. `user.appearance` supplies mpv and Swayimg colors/fonts; mpv retains its packaged color defaults when no palette is selected. Hardware decoding remains a host fact owned by the hardware feature.

Outputs include mpv with uosc/MPRIS/autoload/thumbnail scripts and Anime4K shaders, Musicfox, OBS with PipeWire/wlrobs/Vulkan capture plugins, Blender, GIMP, Kdenlive, FFmpeg, ImageMagick, and Swayimg. Swayimg is the only image viewer registered by this feature. Its locked 4.7 build reports BMP, PNM, TGA, DICOM, JPEG, PNG, GIF, WebP, SVG, HEIF (including HEIC), AVIF, JXL, EXR, TIFF, Sixel, and RAW support; its nixpkgs recipe links the matching decoder libraries. The feature registers video and image MIME handlers and publishes a visible Swayimg desktop entry.

mpv subtitles and OSD use bright text with a deep outline and monospace readouts. uosc opens as a plain canvas with no top bar, persistent timeline, or side volume slider. A 28px native control row combines play/pause, the seek track and time readouts, menu, and fullscreen; it appears near the pointer and fades when the pointer leaves. The main menu retains subtitles, audio tracks, chapters, and playlist; direct keys are `s`, `a`, `c`, `p`, and `Tab` for the main menu. Wheel volume, arrow seeking, Space, MPRIS, autoload, thumbfast, evafast and Anime4K are retained.

mpv's portable default is `hwdec=auto-safe` with `vo=gpu-next` and `gpu-api=vulkan`; this allows safe hardware decoders, including VA-API where the backend/codec is supported, and falls back to software. The selected Legion host provides Intel iHD (`intel-media-driver`) and oneVPL. This configuration makes hardware decode eligible; it does not prove that playback selected it. For a runtime check use a codec/profile listed by `vainfo --display drm --device /dev/dri/renderD128`, run `mpv --msg-level=vd=debug,ffmpeg=debug <file>`, and confirm its `Using hardware decoding` / `vaapi` output. `intel_gpu_top` should show Video activity on the Intel device. No real video playback or GPU activity measurement was performed for this change.

`resources/compact-uosc.py` adapts the locked uosc 5.12 geometry and drawing behind the local `compact_rail` option. It keeps native seek/drag/thumbnail and button/menu handlers, reserves space for time readouts, and draws a 2px horizontal track with a small position marker. While the compact rail is visible (including hover/flash/fade), bottom-aligned plain-text subtitles reserve its height plus an 8px gap through temporary `sub-margin-y`. Hiding the rail, ending the file or shutting down restores the user's baseline. Live user/profile changes are retained, and an already larger margin stays intact. `sub-pos`, watch-later choices and authored ASS styles are unchanged; positioned ASS and bitmap subtitles do not use this plain-text margin and need separate validation. The helper `resources/uosc-subtitle-margin.lua` is exercised by `resources/test-uosc-subtitle-margin.lua` for resize, hide, end-file, shutdown and external-setting changes.

`resources/refine-uosc.py` continues to supply neutral menu/control selections and the blue selected-row marker. Both adaptations check upstream anchors and fail the build if those anchors change. The compact layout is paired with `play-pause,space,menu,fullscreen`; changing that control order also requires reviewing its reserved track geometry. The `mpv-compact-uosc` check compiles patched Lua and loads the real script with the declared options in mpv; it does not prove GUI interaction or hardware decoding.

Swayimg uses the system One Dark background, 128px thumbnails with 12px spacing, and a 1px blue focus outline. Information starts hidden in viewer and gallery; `i` toggles it, and `info_timeout=0` leaves explicitly requested information visible until the next toggle. Viewer shortcuts are Left/Right or h/l for previous/next, r/Shift+r to rotate, f to fit, 1 for original size, Delete for a Zenity confirmation followed by moving the image to Trash, Ctrl+c to copy a PNG representation of the first frame to the active Wayland/X11 clipboard, and Ctrl+g to open the file in GIMP. Shift+Delete and d are explicitly disabled in viewer and gallery; gallery deletion is also disabled, so browsing thumbnails cannot invoke the trash action. With `list.fsmon=yes`, moving the current file to Trash produces a remove event; the viewer removes it from the list and advances.

The upstream Swayimg 4.7 `exec` action substitutes `%` verbatim before invoking `$SHELL -c`. The local `swayimg-package.nix` patch adds `%q`, which quotes the path as one POSIX shell word while preserving the upstream `%` and `%%` behavior. Delete, Ctrl+c, and Ctrl+g use `%q`, including for paths containing single quotes, `$()`, backticks, and newlines. The scoped C regression check executes the patched expression with those names and confirms the metacharacters remain literal.

Owned files are `default.nix`, `blender.nix`, `images.nix`, `swayimg-package.nix`, `checks.nix`, `mpv.nix`, `musicfox.nix`, `obs-studio.nix`, `resources/swayimg-shellcmd-safe-path.patch`, `resources/swayimg-shellcmd-check.c`, `resources/refine-uosc.py`, `resources/compact-uosc.py`, `resources/uosc-subtitle-margin.lua`, and `resources/test-uosc-subtitle-margin.lua`; these implementation files are private to the feature except `checks.nix`, the explicitly registered public test hook. `images.nix` owns the Swayimg INI and its three scoped helper executables (confirmed trash, clipboard conversion, and detached GIMP open). Removing the feature removes package, MIME, and configuration declarations, while media libraries, OBS profiles/recordings, Blender projects, images, and other user data remain on disk. The viewer check verifies the rendered configuration and the locked binary's advertised decoder formats; the shell check compiles the locked upstream helper with the local patch and tests safe path expansion. GUI appearance and decoder runtime still require the isolated screenshot/runtime verification for this round.

The retired Bilibili terminal client is no longer installed. Its existing XDG config/data/cache directories and `~/Videos/Bilibili/` downloads remain user-owned and are not removed. mpv, FFmpeg and all media tools above remain installed for their independent use.
