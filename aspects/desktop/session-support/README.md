# Graphical session support

Provides shared support consumed by graphical sessions: input method, GTK/Qt, fonts, portal/audio/polkit host support, environment, Xresources, and session target wiring. Inputs are host/user appearance palettes, host facts where hardware/display details apply, and the selected session's target names.

The public module option is `nixDotfiles.graphicalSessionTargets`; session features contribute their targets and shared modules use that list to attach session-scoped services. This aspect also selects the shared `workspace-task` utility and grants the input group to users who select graphical support. It does not select or start a compositor.

`default.nix`, `session-targets.nix`, `input-method.nix`, `gtk.nix`, `qt.nix`, `xresources.nix`, `environment.nix`, `tools.nix`, and `host/` implement the feature. The selected GTK3 theme is **adw-gtk3-dark**, with **Tela-circle-dark** icons (the package's default blue variant). The shared appearance names the icon theme once; GTK, Qt's initial defaults, and the Xorg Dunst adapter consume it. There is no Papirus recolor transform. Cursor ownership and the existing environment mirror remain unchanged.

GTK/Qt color templates live in `resources/gtk/` and `resources/qt/`. `resources.nix` copies the final Noctalia package's complete asset bundle, substitutes palette font families, and replaces only its three color templates. Noctalia retains sole runtime ownership of `gtk-3.0/noctalia.css`, `gtk-4.0/noctalia.css`, the import hooks, and `qt6ct/colors/noctalia.conf`; Home Manager does not symlink GTK CSS. The exact color tokens use `colors.onedark_*_value.default.hex`: in locked Noctalia 5.3, unsuffixed custom colors are Material tonal roles even with `blend=false`. The GTK3 Thunar design uses a deep toolbar/sidebar, selection fill with a blue sidebar marker, rounded breadcrumb path and active underline, small monospace headers, and monospace status values. Filenames keep the sans family. Thunar 4.20's actual sidebar class is `.shortcuts-pane`.

Thunar's icon renderer multiplies selected icons by the computed selection `background-color`. The Exo `widget.view:selected/:active` override keeps that color transparent and paints the label fill with a solid selection-colored gradient instead, preserving the icon's original colors in both focus states. GtkTreeView exposes no per-column cell nodes: details/file-chooser selection uses the fill without an inset on every cell. GTK3 has no uppercase text transform, so headers retain their native text. Sidebar width, window geometry, and zoom remain user state. GTK4/libadwaita uses legacy symbolic colors plus current CSS custom properties, keeps native geometry, and gives suggested actions the same neutral selection fill/blue underline. Application-private styles can still take precedence; one Calculator preview does not certify every GTK4 application.

Qt uses Fusion, the 22-role QPalette, and an HM-owned `~/.config/qt6ct/qss/one-dark.qss`. The QSS provides rounded fields/buttons, neutral selection, blue focus/tab indicators, and thin separators; Qt-private or Qt Quick drawing may bypass it. `qt6ct.conf` remains a GUI-owned regular file: activation seeds a missing file and performs a bounded migration of complete former/default font values, the former `Papirus-Dark` icon default, and the managed QSS reference. It preserves custom icons, styles, fonts, unknown sections, and existing stylesheet order, appending only the missing managed path. This path is re-added on later activation if removed through the GUI. Unknown typed values, hexadecimal escapes, and @@-escaped list strings are conservatively left unchanged instead of risking a changed user path. Font strings and stylesheet lists follow real QSettings INI quoting; the ten-field QFont format uses legacy normal weight 50 (400 in that format becomes weight 900 under Qt 6); CRLF and idempotency are tested. File/parent symlinks are refused for both seed and migration. The palette remains a missing-only seed plus Noctalia's existing runtime writer. No activation runs a theme GUI or reloads an application. Fresh Xorg-only accounts retain the existing GTK writer boundary: the base GTK theme is installed, while full GTK palette CSS is supplied when the selected Noctalia lifecycle has generated it; Qt gets its independent initial palette.

`theme-check.nix`, registered as `gtk-qt-theme` through `checks.nix`, builds the theme/icon dependencies, renders the actual templates with the locked offline Noctalia engine (no hooks), parses GTK3/GTK4 with native CSS providers, and verifies Qt defaults/migration with a real QSettings reader. It exports the rendered CSS/palette/QSS for isolated previews. These build checks do not activate a user configuration.

Rime-specific source and packaging live under `rime/`; `rime-checks.nix` and the nested `rime/README.md` document that implementation. No files here are public Nix imports other than the registered feature entry and the declared module option.

Removing shared support removes its settings, host services, group contribution, and Noctalia asset-bundle environment contribution after activation. It preserves input-method dictionaries/history and user GTK/Qt application data. Session-owned targets disappear with their consuming session features.

`checks.nix` is the public test hook for GTK/Qt theme, Rime runtime, and shared visual configuration checks, taking the standard check arguments as needed. Private class and resource modules are not public imports.

Pointer configuration remains owned by the existing HM `home.pointerCursor` declaration: Bibata Modern Classic, 24 logical pixels, GTK and Xresources enabled. `environment.nix` reads that declaration's name/size and mirrors `XCURSOR_THEME`/`XCURSOR_SIZE` into systemd user services as well as shell sessions. Mango forwards those safe values and Xorg sources HM's session variables, so Qt/Kitty receive the same cursor without another theme writer.

ClassicUI sets `PreferTextIcon=True` so Fcitx's native StatusNotifier pixmap uses the engine submode label (Rime Chinese/English), rather than a static named icon. Noctalia pins that existing Fcitx item; shared support adds no second status daemon or input-method writer.
