# Graphical session support

Provides shared support consumed by graphical sessions: input method, GTK/Qt, fonts, portal/audio/polkit host support, environment, Xresources, and session target wiring. Inputs are host/user appearance palettes, host facts where hardware/display details apply, and the selected session's target names.

The public module option is `nixDotfiles.graphicalSessionTargets`; session features contribute their targets and shared modules use that list to attach session-scoped services. This aspect also selects the shared `workspace-task` utility and grants the input group to users who select graphical support. It does not select or start a compositor.

`default.nix`, `session-targets.nix`, `input-method.nix`, `gtk.nix`, `qt.nix`, `xresources.nix`, `environment.nix`, `tools.nix`, and `host/` implement the feature. GTK/Qt palette templates are under `resources/gtk/` and `resources/qt/`; `resources.nix` makes a complete asset bundle from the final Noctalia package and replaces only those three templates. Noctalia keeps sole runtime ownership of `gtk-3.0/noctalia.css`, `gtk-4.0/noctalia.css`, and the mutable qt6ct color scheme. Its existing built-in template IDs and hooks remain enabled. The GTK3 overrides target adw-gtk3 and Thunar's `.thunar`, `.sidebar`, and `.standard-view` classes; Thunar paths, table headers, details-view cells (including filenames; GtkTreeView has no per-cell CSS nodes), and status values use the shared monospace family, and selected rows use the palette selection surface with a narrow blue inset marker. GTK4/libadwaita internals and user window geometry remain controlled by each application. Qt uses Fusion and QPalette colors; QPalette does not control Qt widget radii or spacing. Papirus offers only named variants, so the package keeps its blue folder alias and recolors the locked blue folder artwork's two source fills to the palette blue while preserving the icon paths and shapes.

Rime-specific source and packaging live under `rime/`; `rime-checks.nix` and the nested `rime/README.md` document that implementation. No files here are public Nix imports other than the registered feature entry and the declared module option.

Removing shared support removes its settings, host services, group contribution, and Noctalia asset-bundle environment contribution after activation. It preserves input-method dictionaries/history and user GTK/Qt application data. Session-owned targets disappear with their consuming session features.

`checks.nix` is the public test hook for the Rime runtime check and the shared visual configuration check, taking the standard check arguments as needed. Private class and resource modules are not public imports.

Pointer configuration remains owned by the existing HM `home.pointerCursor` declaration: Bibata Modern Classic, 24 logical pixels, GTK and Xresources enabled. `environment.nix` reads that declaration's name/size and mirrors `XCURSOR_THEME`/`XCURSOR_SIZE` into systemd user services as well as shell sessions. Mango forwards those safe values and Xorg sources HM's session variables, so Qt/Kitty receive the same cursor without another theme writer.

ClassicUI sets `PreferTextIcon=True` so Fcitx's native StatusNotifier pixmap uses the engine submode label (Rime Chinese/English), rather than a static named icon. Noctalia pins that existing Fcitx item; shared support adds no second status daemon or input-method writer.
