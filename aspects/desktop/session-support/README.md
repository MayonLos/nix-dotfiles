# Graphical session support

Provides shared support consumed by graphical sessions: input method, GTK/Qt, fonts, portal/audio/polkit host support, environment, Xresources, and session target wiring. Inputs are host/user appearance palettes, host facts where hardware/display details apply, and the selected session's target names.

The public module option is `nixDotfiles.graphicalSessionTargets`; session features contribute their targets and shared modules use that list to attach session-scoped services. This aspect also selects the shared `workspace-task` utility and grants the input group to users who select graphical support. It does not select or start a compositor.

`default.nix`, `session-targets.nix`, `input-method.nix`, `gtk.nix`, `qt.nix`, `xresources.nix`, `environment.nix`, `tools.nix`, and `host/` implement the feature. The selected GTK3 theme is **adw-gtk3-dark**, with **WhiteSur-dark** icons (nixpkgs package default, blue folders). The shared appearance names the icon theme once; GTK, Qt initial defaults, KDE and the Xorg Dunst adapter consume it. There is no Papirus recolor transform. The package cursor is **macOS-White**, 32 logical pixels; the existing Xcursor environment mirror forwards that setting to shell and systemd user services. Inter uses 10.5 pt in GTK and in qt6ct’s serialized QFont default; Qt’s ten-field format accepts fractional point sizes. The QSS leaves widget font family and base size to the GUI-owned Qt font setting, while styling targeted control/title weights. Maple remains 11 pt for code/terminals; GTK paths/entries and UI metadata use the sans hierarchy (14/13 px), and Qt headers inherit the user GUI font with 500 weight rather than forcing a small monospace font.

GTK/Qt color templates live in `resources/gtk/` and `resources/qt/`. `resources.nix` copies the final Noctalia package's complete asset bundle, substitutes palette font families and exact One Dark color literals, and replaces only its three color templates. Noctalia retains sole runtime ownership of `gtk-3.0/noctalia.css`, `gtk-4.0/noctalia.css`, the import hooks, and `qt5ct/colors/noctalia.conf` / `qt6ct/colors/noctalia.conf`; Home Manager does not symlink GTK CSS. The source expressions `colors.onedark_*_value.default.hex` are resolved by Nix before these builtin assets reach Noctalia. Locked Noctalia 5.4 constructs its builtin engine without `theme.templates.custom_colors`; only the user-template engine receives them. Keeping the original builtin IDs/catalog preserves GTK extension indices, apply/import and undo hooks. Moving these entries to user templates would lose builtin undo support because the user schema has no `undo_hook`. Firefox remains a user template with exact `_value` custom colors. The GTK3 Thunar design uses a deep toolbar/sidebar, selection fill with a blue sidebar marker, rounded breadcrumb path and active underline, small monospace headers, and monospace status values. Filenames keep the sans family. Thunar 4.20's actual sidebar class is `.shortcuts-pane`.

Thunar's icon renderer multiplies selected icons by the computed selection `background-color`. The Exo `widget.view:selected/:active` override keeps that color transparent and paints the label fill with a solid selection-colored gradient instead, preserving the icon's original colors in both focus states. GtkTreeView exposes no per-column cell nodes: details/file-chooser selection uses the fill without an inset on every cell. GTK3 has no uppercase text transform, so headers retain their native text. Sidebar width, window geometry, and zoom remain user state. GTK4/libadwaita uses legacy symbolic colors plus current CSS custom properties, keeps native geometry, and gives suggested actions the same neutral selection fill/blue underline. Application-private styles can still take precedence; one Calculator preview does not certify every GTK4 application.

Qt uses Fusion, the 22-role QPalette, and an HM-owned `~/.config/qt6ct/qss/one-dark.qss`. `qt-style.nix` is its public `{ pkgs, palette }` factory; it returns the shared `stylesheet` and Prism's `themeManifest` plus indicator image paths. The QSS gives group boxes consistent backgrounds, distinct checked/unchecked/mixed/disabled checkbox and radio states, tighter controls, neutral selection, blue focus/tab indicators, and thin separators; Qt-private or Qt Quick drawing may bypass it. Prism's own widget theme replaces qt6ct's application stylesheet at startup, so gaming installs this generated QSS as a base, adds Prism-only control refinements, and supplies the complete One Dark palette in `~/.local/share/PrismLauncher/themes/OneDark/{theme.json,themeStyle.qss}`. Prism's GUI-owned `ApplicationTheme` stays untouched; select `One Dark` once in Prism's Settings → Appearance → Theme to apply it. The two theme files are HM-managed; `gaming/checks.nix` checks their palette and shared stylesheet wiring, while `gtk-qt-theme` renders the actual checkbox and group-box state matrix with Qt. `qt6ct.conf` remains a GUI-owned regular file: activation seeds a missing file and performs a bounded migration of complete former/default font values, the former `Papirus-Dark` and `Tela-circle-dark` icon defaults, and the managed QSS reference. It preserves custom icons, styles, fonts, unknown sections, and existing stylesheet order, appending only the missing managed path. This path is re-added on later activation if removed through the GUI. Unknown typed values, hexadecimal escapes, and @@-escaped list strings are conservatively left unchanged instead of risking a changed user path. Font strings and stylesheet lists follow real QSettings INI quoting; the ten-field QFont format uses legacy normal weight 50 (400 in that format becomes weight 900 under Qt 6); CRLF and idempotency are tested. File/parent symlinks are refused for both seed and migration. The palette remains a missing-only seed plus Noctalia's existing runtime writer. No activation runs a theme GUI or reloads an application. Fresh Xorg-only accounts retain the existing GTK writer boundary: the base GTK theme is installed, while full GTK palette CSS is supplied when the selected Noctalia lifecycle has generated it; Qt gets its independent initial palette.

`template-runtime-check.nix`, registered as `noctalia-template-runtime`, runs the locked `noctalia theme --config` in a Nix sandbox with private HOME/XDG and no display/session bus. It projects the production enabled builtin catalog without injecting custom colors, runs real hooks, verifies four overwritten GTK/Qt outputs and GTK imports, and exercises every enabled user template (Firefox, Zathura, Obsidian) with a registered vault/profile fixture. Output contents must contain exact One Dark colors and successful apply/repeat logs must contain no template errors. A negative control reproduces all four old failures and stale files; builtin undo scripts must remove only managed files/imports. Newly added user entries require explicit output/hook fixtures. `gtk-qt-theme` parses these applied outputs with native GTK3/4 providers and verifies Qt defaults/migration with real QSettings/QFont. The CLI is the closest standalone path: v5.4 has no headless TemplateApplyService entrypoint (`templates-apply` is IPC), so service scheduling, state bookkeeping and community extension synchronization remain outside this check. These checks do not activate a user configuration or start a daemon.

Rime-specific source and packaging live under `rime/`; `rime-checks.nix` and the nested `rime/README.md` document that implementation. Public Nix imports are the registered feature entry, `checks.nix`, and the `qt-style.nix` package factory described above; other implementation files are private. The declared module option remains public.

Removing shared support removes its settings, host services, group contribution, and Noctalia asset-bundle environment contribution after activation. It preserves input-method dictionaries/history and user GTK/Qt application data. Session-owned targets disappear with their consuming session features.

`checks.nix` is the public test hook for GTK/Qt theme, Rime runtime, and shared visual configuration checks, taking the standard check arguments as needed. Private class and resource modules are not public imports.

Pointer configuration remains owned by the existing HM `home.pointerCursor` declaration: `pkgs.apple-cursor` / macOS-White, 32 logical pixels, GTK and Xresources enabled. `environment.nix` reads that declaration's name/size and mirrors `XCURSOR_THEME`/`XCURSOR_SIZE` into systemd user services as well as shell sessions. Mango forwards those safe values and Xorg sources HM's session variables, so Qt/Kitty receive the same cursor without another theme writer.

ClassicUI sets `PreferTextIcon=True` so Fcitx's native StatusNotifier pixmap uses the engine submode label (Rime Chinese/English), rather than a static named icon. Noctalia pins that existing Fcitx item; shared support adds no second status daemon or input-method writer.


Round 26 adds an HM-owned `kdeglobals` and matching `color-schemes/NixDotfilesOneDark.colors`, generated from the same appearance palette. KDE ColorScheme readers receive dark Window/View/Button/Selection colors, WhiteSur-dark icons, Fusion, and menu/button icon preferences. These two files are declarative; private Qt renderers can bypass them. Qt6ct's `Appearance/standard_dialogs` is now a managed field set to `xdgdesktopportal` on new and existing regular configurations, with the existing symlink guard and other GUI fields preserved. GTK3/4 clients receive `GTK_USE_PORTAL=1` in shell and systemd environments; Mango's safe environment projection forwards it. Both session portal configurations already route FileChooser to GTK, while Settings uses GTK in both sessions. `application-portals-theme` checks these routes, environment, and generated KDE files; the existing real Qt theme check verifies seed and migration. Applications can explicitly request a non-native/self-drawn dialog, which environment settings cannot override.

GTK2 uses the installed Adwaita-dark engine from `gnome-themes-extra` and HM-owned One Dark widget roles. The shared `GTK_PATH` points to the package’s `lib/gtk-2.0` search root so GTK2 can load its 2.10.0 engine while GTK3 searches its own ABI directory; adw-gtk3 alone does not provide GTK2 assets. Its legacy native chooser cannot use GTK3/Qt portal APIs.

Round 37 removes the GNOME portal backend: GTK supplies Settings and FileChooser without Mutter; Secret Service remains gnome-keyring and Mango capture remains wlr. `host/portal-common.nix` owns the generated D-Bus configuration through the upstream `makeDBusConf` factory. `host/deduplicate-dbus.py` preserves policy includes and first-provider precedence, merges explicit service directories by bus name, and leaves standard XDG user discovery enabled. Session services already in the system profile are not registered again; `service-providers.json` records providers and duplicate sources for audit. This removes redundant activation registrations without removing their packages or systemd units. Upstream Tumbler filenames in the system profile are unchanged. The unused legacy PipeWire X11 bell module is disabled for both sessions; ordinary audio and notification sounds remain available. Removing this feature restores upstream bus configuration and withdraws its portal/audio settings; keyring data and application state are retained.
