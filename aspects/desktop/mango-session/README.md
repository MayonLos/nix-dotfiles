# Mango session

Provides the Mango Wayland desktop and its Noctalia shell integration. Inputs are `user.appearance`, host display facts, selected `noctaliaIntegrations`, and the public `nixDotfiles.graphicalSessionTargets` option from session support.

Outputs include Mango/Noctalia configuration, clipboard bridges, screenshot and OCR tools, per-session environment, and host-side Mango/portal modules routed through `interactive-session-host`. The `noctaliaIntegrations` quirk is declared here and validated by `contract.nix` before it is consumed to render selected application integrations. The feature owns its session target and Noctalia service lifecycle; it does not select the login greeter.

Noctalia settings are rendered by `noctalia.nix`; its package is built from the locked `pkgs.local.noctalia` derivation with `noctalia/astra-selection.patch`. The patch keeps launcher selection and active Home shortcuts on a faint palette hover surface, uses blue foregrounds, adds minimal workspace underlines/occupancy dots, and turns the Home layout into a vertical stack with a full-width three-column shortcut grid. The same patch inserts native volume/brightness sliders between the grid and media card; Home uses no sidebar and its configured width is not reduced by the native sidebar multiplier. Brightness commits when a drag/key step completes; its value reads the first controllable display and changes all controllable displays. The bar follows the HUD Line design at 30 logical pixels: a near-black palette backdrop, faint blue outline, fading blue-to-cyan upper rule, native faded separators, and blue workspace underline/glow. Workspaces 1–5 stay visible along with active, urgent, or occupied later workspaces. The layout label is outlined; hovering Quill reveals the blue inset tools group (Quill, Docker, ports, brightness, power profile, caffeine). Docker omits a zero count, ports use `11 ports`, and the power profile includes its actual mode name. Date, luminous dot and bold Maple Mono time share the center. The always-visible native sysmon group uses a blue CPU graph, green RAM ring and orange temperature; NVIDIA usage/temperature and VRAM are removed from layout while unavailable. `system.monitor.gpu_only_nvidia` prevents Intel fallback even when the NVIDIA PCI function disappears; a two-second retained sampler can restore the indicators after power-up, clears failed/stale samples, uses short NVML sessions that release handles after each poll, clears readers while suspended, and retries unavailable NVML initialization. The Nix status capsule combines the active generation and update marker. The system group retains Wi-Fi, Bluetooth, volume percentage, the pinned Fcitx tray indicator, the native graphic battery/percentage with its conservation click action, and a red unread-notification dot. SYSTEM, DISPLAY, network, Bluetooth, volume and battery tooltips use structured headings, native graphs/progress and metric grids; DISPLAY uses a manufacturer/display-kind name and current output mode rather than a raw EDID/serial description. The pinned nix-status and nix-search plugins remain enabled, with `nix-search-tv` and `fzf` declared as runtime packages. Targeted read-only inspection confirmed the old managed file omitted `shell.app_icon_colorize` while the runtime sidecar set it to true, causing grayscale/tint. The new managed false value is covered by the existing public-key reconciliation; no runtime state was changed during implementation. Launcher icons preserve their source colors; launcher, control center, and notification widths are 560, 380, and 320 logical pixels.

Legion conservation mode is exposed through a local Noctalia status plugin, which polls the host command asynchronously and displays green `养护` only while active. The battery widget's left click invokes `legion-conservation toggle`; the command itself is supplied by the separately owned `hardware/legion-laptop` feature. The community plugin source keeps its original `community` identity and all untouched plugin directories as store symlinks. A build-time overlay copies only `mango_layouts`, `nix-status`, `mini-docker` and `portctl`: it adds the plugin's `zh-CN` translations and reads the active generation number by matching `/run/current-system` to `/nix/var/nix/profiles/system-N-link`. The nix-status details panel and service remain intact. The pure generation-number parser test is `resources/noctalia-community/nix-status/tests/generation_number_test.luau`; run it from the patched plugin directory with `luau tests/generation_number_test.luau` when Luau is available. The feature also supplies the pinned Neovim terminal desktop entry and `notify-send` (`libnotify`) for notification review. The managed Noctalia user service sets `LC_TIME=zh_CN.UTF-8` for Chinese date labels. `runtime-check.nix` runs the locked binary's `config validate` and checks serialized UI settings; this is build-time validation, not a live desktop session test.

Noctalia settings are rendered by `noctalia.nix`; its package is built from the locked `pkgs.local.noctalia` derivation with `noctalia/astra-selection.patch`, `noctalia/tech-lockscreen.patch`, `noctalia/tech-osd-segments.patch`, and the `noctalia/hud-*.patch` set. The HUD patches extend native bar decorations, structured tooltips, compact monitor visualization and unavailable-GPU handling; each has source-marker checks in `postPatch`, and the serialized bar contract is asserted by `interactive-session-config`. The lock-screen time/date widgets use the palette monospace family, with seconds in a separate smaller palette-outline widget. The password field owns a 2 px blue-to-cyan palette underline and a soft translucent accent directly beneath it. A monospace footer shows the current user/host, kernel release, and battery capacity/state, refreshing its sysfs readout every five seconds. The feature also supplies the pinned Neovim terminal desktop entry and `notify-send` (`libnotify`) for notification review. The managed Noctalia user service sets `LC_TIME=zh_CN.UTF-8` for Chinese date labels.

The pinned Noctalia v5.3.0 login-box `show_session_buttons` setting controls lock-screen power actions and only renders in the regular layout; it does not select the next login session. The locked Greeter owns Mango/Xorg login-session selection. The footer first reads `conservation_mode` from discovered devices under the generic `ideapad_acpi` driver directory (`1`/`0` means on/off, only after a complete traversal with consistent values), then falls back to the battery `charge_control_end_threshold`: a valid 1–100% limit at or below 80% is shown as active maintenance and a higher limit as off. If neither source yields a valid value, it shows `养护 --`. The OSD patch overlays nineteen palette-surface separators to make twenty segments on the native progress bar and sets its value label to monospace before measuring its reserved width. `postPatch` checks each patch's key source markers, including clearing non-owning tick pointers before scene-tree rebuild, so source drift fails the build rather than silently losing the design. When upgrading Noctalia, inspect the locked source, refresh each narrow patch, preserve its marker checks, then build the package before accepting the update.

`default.nix` and `contract.nix` are public. `mango.nix`, `noctalia.nix`, `noctalia/`, `clipboard.nix`, `screenshot.nix`, `tesseract-ocr.nix`, and `host/` are private implementation. `checks.nix` is a public test hook with signature `{ pkgs, lib, system, nixos, home, appearance }` (as needed). Other Nix files are private.

Removing the feature withdraws Mango and Noctalia configuration, session services, and screenshot/clipboard declarations when a new generation is activated. It leaves user documents, Noctalia history/settings outside declared paths, saved sessions, and other application state untouched; it does not stop or switch the running session by itself.

HM owns `Pictures/Wallpapers/managed` as a store link. The `wallpaperLocalDirectory` activation only creates a missing `Pictures/Wallpapers/local/`, preserves existing directories and directory symlinks, and refuses other existing objects without replacement. Noctalia scans the parent recursively, following directory symlinks with canonical-path deduplication. User local images remain outside Git/store and survive feature removal. Native automation also chooses a random image at shell startup; the declared default and greeter use wallpaper-005.png, while the lockscreen follows the current desktop wallpaper.

Mango uses the locked upstream flake package directly, with identical host/HM defaults. Focus is a native 2 px palette-blue border; only floating clients receive black alpha 0x52 shadows (10 px size, 20 px blur, 6 px downward offset). Native dim uses black alpha 0x10 (6.3%) over inactive windows; clients remain opaque. `client_draw_dim()` in 0.18.3 exempts fullscreen automatically. There is **no per-window `no_dim` option** in that version: floating PiP also receives this light dim. `unfocused_opacity=1` cannot override it. No extra compositor patch is installed. Opens, moves and tag changes use 180 ms, closes 160 ms, all with the same ease-out curve; `reducedMotion` still disables animation.

## Window rules

The single private table is `mango/window-rules.nix`. It is imported once by `mango.nix`; change app IDs/titles there. `interactive-session-config` runs the actual locked `mango -c config.conf -p` parser, rejects parser diagnostics, and runs generated-rule regression fixtures for matching and false positives. Parser success does not establish that a proprietary application's live app ID/title matches the proposed pattern.

| Windows | Default and reason |
|---|---|
| Native transient dialogs | Mango detects parent / dialog type, floats and centers natively; parent workspace and application size hints remain authoritative. |
| File chooser / portal | Exact common English/Chinese picker titles for Firefox/Thunar and standalone GTK/GNOME portal helpers float at 60% × 65%. A documentation tab containing “Save As” does not match. |
| polkit / pinentry | Standalone agents float at 38% × 32%; Noctalia's built-in polkit is a shell surface and needs no top-level rule. Patterns also cover the optional Xorg agent if used under Mango. |
| Firefox PiP | Floating, overlay, global on the current output, silent; initial 480 × 270, right/bottom offsets 96/92. Native size hints remain enabled. Mango has no aspect-ratio lock: 16:9 is an initial size, and the client owns video proportions. Overlay also appears over fullscreen clients; toggle it with the existing `Super+Alt+G` if unwanted. |
| mpv / imv / swayimg | Floating 60% × 64%, centered. Client-requested fullscreen still works and bypasses dim natively. |
| pavucontrol / blueman / NetworkManager editor | Floating 34% × 52%, near the upper-right bar; useful temporary controls without changing tiled work. |
| Calculator / color picker / mark-shot | Small floating tools. mark-shot's capture surface remains layer-shell; only its editor is a top-level target, with animation disabled. |
| Steam / Minecraft | Game app IDs disable border/shadow/radius/animation. Fullscreen remains the game's request so helpers are not forcibly enlarged. `allow_tearing=2` limits tearing to fullscreen; a catch-all rule opts normal clients out and only game IDs opt in. Driver/output support is still required; no DRM environment workaround is added. |
| Steam Friends / notifications | Friends gets a narrow floating window; title-matched notifications open silently. Main Steam stays unchanged. |
| Prism Launcher | Instance settings / console windows float; launcher and game lifetime are unaffected. |
| QQ / WeChat / Discord / Vesktop / Tencent Meeting | Only title-matched notification, sharing toolbar and mini-window surfaces float silently. Main chats, login and meeting windows can still take keyboard focus. Proprietary titles must be checked after application; normal calls are not globally made unfocusable. |
| Named scratch tools | Existing app IDs, geometry and keybindings retained. |

`focus_on_activate=0` turns unsolicited activation into an urgent hint instead of a view/focus jump. It does not suppress every newly mapped application; specific passive windows use `is_open_silent`/`is_tag_silent`. Explicitly launched normal windows and password dialogs still focus. `no_focus` is intentionally avoided because it also prevents later interaction.

No existing fixed application destinations were found, so tag placement stays under the current `Super+1…9` / move bindings. To opt into browser 2 and communication 4, pass `assignAppTags = true` at the import in `mango.nix`; the table contains narrow main-window patterns and silent assignment. These optional patterns require matching live titles, and Firefox page titles without “Mozilla Firefox” will stay on the current tag. Avoid blanket tags on every browser/communication window, which would relocate dialogs and PiP. Mango `tags` are 1-based, whereas `tag_rule.id` is 0-based.

Rules use the [upstream rules reference](https://mangowm.github.io/docs/window-management/rules/) and community wiki examples, checked against locked revision `900b8d7` (`option_defs.c`, `client.c`, `animation/client.c`, `ext-protocol/tearing.c`). Newer documentation may describe options absent in 0.18.3. Optional app patterns install no additional applications.

## Bar and pointer details

The battery uses Noctalia `display_mode="graphic"` with `label_outside=true`: native outlined body, inset green fill and terminal geometry, followed by a separate monospace percentage. Low charge keeps the configured warning color. The local option changes horizontal bars; default and vertical rendering remain native. Both the old `glyph` path and the native Graphic label embedded inside the filled body were ambiguous at this size. The standalone XKB `keyboard_layout` component has been removed: its SNI tooltip fallback names the input method but cannot reliably express Rime's internal Chinese/English submode. The tray now sits in the visible system group with `drawer=true` and `pinned=["fcitx"]`; shared support enables `ClassicUI.PreferTextIcon=True` so Fcitx's native SNI image reflects its engine submode label, and other tray apps remain in the drawer. Real Rime toggles still require session acceptance; no polling daemon or simulated keys were added. Layout labels remain native English even in the `zh-CN` plugin translation.

Bibata Modern Classic 24 is already the shared pointer default. At output scale 1.5 this corresponds to a nominal 36 device pixels. Mango consumes that palette directly; shared support mirrors HM's `XCURSOR_THEME`/`XCURSOR_SIZE` into the user manager and the compositor's safe environment. GTK and Xresources keep their existing sole declaration, Qt/Kitty inherit the same Xcursor environment, and Xorg sources HM session variables. No Hyprcursor configuration is needed.
