# Mango session

Provides the Mango Wayland desktop and its Noctalia shell integration. Inputs are `user.appearance`, host display facts, selected `noctaliaIntegrations`, and the public `nixDotfiles.graphicalSessionTargets` option from session support.

Outputs include Mango/Noctalia configuration, clipboard bridges, screenshot and OCR tools, per-session environment, and host-side Mango/portal modules routed through `interactive-session-host`. The `noctaliaIntegrations` quirk is declared here and validated by `contract.nix` before it is consumed to render selected application integrations. The feature owns its session target and Noctalia service lifecycle; it does not select the login greeter.

Noctalia settings are rendered by `noctalia.nix`; its package is built from the locked `pkgs.local.noctalia` derivation with the local `noctalia/*.patch` series; each source patch has build-time drift checks in `noctalia.nix`. After the r32 input update, managed role references use `surface_container` and `outline_variant` (the custom palette JSON still uses its supported `mSurfaceVariant`/`mOutline` keys). the slider track and tooltip surface use upstream OutlineVariant boundaries; the former tooltip gradient and blue/cyan top rule are removed so tooltips share the opaque single-outline panel treatment. Sysmon patches retain the updated per-core gauge and network decimal precision APIs without enabling extra bar content. The patch keeps launcher selection and active Home shortcuts on a faint palette hover surface, uses blue foregrounds, adds minimal workspace underlines/occupancy dots, and turns the Home layout into a vertical stack with a full-width three-column shortcut grid. The same patch inserts native volume/brightness sliders between the grid and media card; Home uses no sidebar and its configured width is not reduced by the native sidebar multiplier. Brightness commits when a drag/key step completes; its value reads the first controllable display and changes all controllable displays. The bar uses the approved R31 single-panel layout: 35 logical pixels, a flat One Dark surface, one low-contrast 1 px outline and 9 px corners, without the extra gradient upper rule/glow. Each non-spacer widget keeps scale 1.15 and the bar font scale stays 0.93. Launcher, workspaces, layout and the Quill tools accordion occupy the left; date/time retain the independent center slot. Workspaces 1–5 stay visible along with active, urgent or occupied later workspaces. The active workspace has a faint blue surface and the existing underline; inactive workspace surfaces stay transparent. Occupied dots use the palette outline role at 2 px; empty labels use 60% palette border alpha with the existing dimming. CPU mini graph with 18% area fill, thicker MEM ring and matching cyan GPU ring form one transparent right-side monitoring group, followed by a separator, system controls and the settings glyph. Layout, tools and monitors have no nested capsule outlines. Quill uses muted `icon_color`; the locked plugin sets its glyph from notes/due/overdue state and exposes no glyph setting, and the native plugin widget has no generic glyph override. The approved fallback retains that glyph rather than changing the plugin. Hovering Quill still reveals Docker, ports, brightness, power profile and caffeine; Docker omits zero counts and the power profile keeps its mode in the POWER tooltip. CPU temperature stays hidden below 80°C, orange at 80–89°C and red from 90°C. CPU/MEM/GPU labels use small palette-muted monospace; values are bright foreground monospace, right-aligned in 22 px reserved boxes with roughly 6 logical px internal gaps. Their `warning_threshold=70` and `critical_threshold=90` switch both values and graphs/rings to palette yellow/red inclusively; below 70%, values stay bright and charts use blue/green/cyan. The thresholds, alert colors and `label_color` are sysmon options; zero thresholds preserve native gradients for other widgets. GPU leaves layout entirely when unavailable. The settings glyph uses neutral foreground. The unread notification dot is 5 px with a palette bar-surface outline. VRAM, GPU temperature, frequency, Swap and throughput stay in SYSTEM hover details. The NVIDIA-only two-second sampler, suspend handling and short NVML sessions are unchanged. Both sides reserve 24 logical pixels around the centered clock; the right section measures its full width each pass and uses temperature/GPU dots when necessary, while native section clipping protects the clock on still narrower outputs. Tools accordion and tray drawer remain native interactions. The system group retains Wi-Fi, Bluetooth, icon-only volume, the pinned Fcitx indicator and tray drawer, battery percentage and conservation click action, and notifications. Monitor members use 6 px spacing with 2 px group padding; system members use 8 px spacing. These tighter right-side gaps preserve complete CPU/MEM content at 2048×1280 with 1.5 output scale and a pinned tray icon plus drawer, while keeping all controls reachable. SYSTEM, DISPLAY, network, Bluetooth, volume and battery tooltips use structured headings, native graphs/progress and metric grids; DISPLAY uses a manufacturer/display-kind name and current output mode rather than a raw EDID/serial description. The independent nix-search launcher provider remains enabled, with `nix-search-tv` and `fzf` declared as runtime packages. Targeted read-only inspection confirmed the old managed file omitted `shell.app_icon_colorize` while the runtime sidecar set it to true, causing grayscale/tint. The new managed false value is covered by the existing public-key reconciliation; no runtime state was changed during implementation. Launcher icons preserve their source colors; launcher, control center, and notification widths are 520, 380, and 320 logical pixels. Mango uses 12 px outer gaps, 8 px inner gaps and 10 px window corners; the 2 px focus border remains visible.

Legion conservation mode is exposed through a local Noctalia status plugin, which polls the host command asynchronously and displays green `养护` only while active. The battery widget's left click invokes `legion-conservation toggle`; the command itself is supplied by the separately owned `hardware/legion-laptop` feature. The community plugin source keeps its original `community` identity and all untouched plugin directories as store symlinks. A build-time overlay copies only `mango_layouts`, `mini-docker` and `portctl`, adding Chinese layout translations and compact bar labels. Nix Status is no longer enabled or placed in the bar; its local overlay, generation parser and exclusive badge/min-width API patch have been removed. Existing runtime plugin state is preserved, while the managed enabled list prevents its service from starting. The upstream catalog remains available for explicit manual selection. The feature also supplies the pinned Neovim terminal desktop entry and `notify-send` (`libnotify`) for notification review. The managed Noctalia user service sets `LC_TIME=zh_CN.UTF-8` for Chinese date labels. `runtime-check.nix` runs the locked binary's `config validate` and checks serialized UI settings; this is build-time validation, not a live desktop session test.

Noctalia settings are rendered by `noctalia.nix`; its package is built from the locked `pkgs.local.noctalia` derivation with `noctalia/astra-selection.patch`, `noctalia/tech-lockscreen.patch`, `noctalia/tech-osd-segments.patch`, and the `noctalia/hud-*.patch` set. The HUD patches extend native bar decorations, structured tooltips, compact monitor visualization and unavailable-GPU handling; each has source-marker checks in `postPatch`, and the serialized bar contract is asserted by `interactive-session-config`. The lock-screen time/date widgets use the palette monospace family, with seconds in a separate smaller palette-outline widget. The password field owns a 2 px blue-to-cyan palette underline and a soft translucent accent directly beneath it. A monospace footer shows the current user/host, kernel release, and battery capacity/state, refreshing its sysfs readout every five seconds. The feature also supplies the pinned Neovim terminal desktop entry and `notify-send` (`libnotify`) for notification review. The managed Noctalia user service sets `LC_TIME=zh_CN.UTF-8` for Chinese date labels.

The pinned Noctalia v5.4.0 login-box `show_session_buttons` setting controls lock-screen power actions and only renders in the regular layout; it does not select the next login session. The locked Greeter owns Mango/Xorg login-session selection. The footer first reads `conservation_mode` from discovered devices under the generic `ideapad_acpi` driver directory (`1`/`0` means on/off, only after a complete traversal with consistent values), then falls back to the battery `charge_control_end_threshold`: a valid 1–100% limit at or below 80% is shown as active maintenance and a higher limit as off. If neither source yields a valid value, it shows `养护 --`. The OSD patch overlays nineteen palette-surface separators to make twenty segments on the native progress bar and sets its value label to monospace before measuring its reserved width. `postPatch` checks each patch's key source markers, including clearing non-owning tick pointers before scene-tree rebuild, so source drift fails the build rather than silently losing the design. When upgrading Noctalia, inspect the locked source, refresh each narrow patch, preserve its marker checks, then build the package before accepting the update.

`default.nix` and `contract.nix` are public. `mango.nix`, `noctalia.nix`, `noctalia/`, `clipboard.nix`, `screenshot.nix`, `tesseract-ocr.nix`, and `host/` are private implementation. `checks.nix` is a public test hook with signature `{ pkgs, lib, system, nixos, home, appearance }` (as needed). Other Nix files are private.

Removing the feature withdraws Mango and Noctalia configuration, session services, and screenshot/clipboard declarations when a new generation is activated. It leaves user documents, Noctalia history/settings outside declared paths, saved sessions, and other application state untouched; it does not stop or switch the running session by itself.

HM owns `Pictures/Wallpapers/managed` as a store link. The `wallpaperLocalDirectory` activation only creates a missing `Pictures/Wallpapers/local/`, preserves existing directories and directory symlinks, and refuses other existing objects without replacement. Noctalia scans the parent recursively, following directory symlinks with canonical-path deduplication. User local images remain outside Git/store and survive feature removal. Native automation also chooses a random image at shell startup; the declared default and greeter use wallpaper-005.png, while the lockscreen follows the current desktop wallpaper.

Mango uses the locked upstream flake package directly, with identical host/HM defaults. Focus is a native 2 px palette-blue border; only floating clients receive black alpha 0x52 shadows (10 px size, 20 px blur, 6 px downward offset). Native dim uses black alpha 0x10 (6.3%) over inactive windows; clients remain opaque. `client_draw_dim()` in 0.18.3 exempts fullscreen automatically. There is **no per-window `no_dim` option** in that version: floating PiP also receives this light dim. `unfocused_opacity=1` cannot override it. No extra compositor patch is installed. Opens, moves and tag changes use 180 ms, closes 160 ms, all with the same ease-out curve; `reducedMotion` still disables animation.

## Window rules

The single private table is `mango/window-rules.nix`. It is imported once by `mango.nix`; change app IDs/titles there. `interactive-session-config` runs the actual locked `mango -c config.conf -p` parser, rejects parser diagnostics, and runs generated-rule regression fixtures for matching and false positives. Parser success does not establish that a proprietary application's live app ID/title matches the proposed pattern.

| Windows | Default and reason |
|---|---|
| Native transient dialogs | Mango detects parent / dialog type, floats and centers natively; parent workspace and application size hints remain authoritative. |
| File chooser / portal | Exact common English/Chinese picker titles for Firefox/Thunar and standalone GTK/GNOME portal helpers float at 60% × 65%. A documentation tab containing “Save As” does not match. |
| polkit / pinentry | Standalone agents float at 38% × 32%; Noctalia's built-in polkit is a shell surface and needs no top-level rule. Patterns also cover the optional Xorg agent if used under Mango. |
| Firefox PiP | Floating, overlay, global on the current output, silent; initial 480 × 270, right/bottom offsets 96/92. Native size hints remain enabled. Mango has no aspect-ratio lock: 16:9 is an initial size, and the client owns video proportions. Overlay also appears over fullscreen clients; toggle it with the existing `Super+Alt+G` if unwanted. |
| mpv / imv / swayimg | Floating 60% × 64%, centered. Client-requested fullscreen still works and bypasses dim natively. |
| pavucontrol / blueman / NetworkManager editor | Floating 34% × 52%, near the upper-right bar; useful temporary controls without changing tiled work. |
| Calculator / color picker / mark-shot | Small floating tools. mark-shot's capture surface remains layer-shell; only its editor is a top-level target, with animation disabled. |
| Steam / Minecraft | Game app IDs disable border/shadow/radius/animation. Fullscreen remains the game's request so helpers are not forcibly enlarged. `allow_tearing=2` limits tearing to fullscreen; a catch-all rule opts normal clients out and only game IDs opt in. Driver/output support is still required; no DRM environment workaround is added. |
| Steam Friends / notifications | Friends gets a narrow floating window; title-matched notifications open silently. Main Steam stays unchanged. |
| Prism Launcher | Instance settings / console windows float; launcher and game lifetime are unaffected. |
| QQ / WeChat / Discord / Vesktop / Tencent Meeting | Only title-matched notification, sharing toolbar and mini-window surfaces float silently. Main chats, login and meeting windows can still take keyboard focus. Proprietary titles must be checked after application; normal calls are not globally made unfocusable. |
| Named scratch tools | Existing app IDs, geometry and keybindings retained. |

`focus_on_activate=0` turns unsolicited activation into an urgent hint instead of a view/focus jump. It does not suppress every newly mapped application; specific passive windows use `is_open_silent`/`is_tag_silent`. Explicitly launched normal windows and password dialogs still focus. `no_focus` is intentionally avoided because it also prevents later interaction.

No existing fixed application destinations were found, so tag placement stays under the current `Super+1…9` / move bindings. To opt into browser 2 and communication 4, pass `assignAppTags = true` at the import in `mango.nix`; the table contains narrow main-window patterns and silent assignment. These optional patterns require matching live titles, and Firefox page titles without “Mozilla Firefox” will stay on the current tag. Avoid blanket tags on every browser/communication window, which would relocate dialogs and PiP. Mango `tags` are 1-based, whereas `tag_rule.id` is 0-based.

Rules use the [upstream rules reference](https://mangowm.github.io/docs/window-management/rules/) and community wiki examples, checked against locked revision `900b8d7` (`option_defs.c`, `client.c`, `animation/client.c`, `ext-protocol/tearing.c`). Newer documentation may describe options absent in 0.18.3. Optional app patterns install no additional applications.

## Bar and pointer details

The battery uses Noctalia `display_mode="graphic"` with `label_outside=true`: native outlined body, inset neutral palette-foreground fill at 85% opacity and terminal geometry, followed by a separate bright monospace percentage. Charging uses palette green with a small surface-colored bolt inside the body, without reserving an extra state-icon slot. At ≤20% the outline/fill/value use palette yellow, and at ≤10% they use palette red, including while charging. `graphic_color`, `charging_color`, `critical_color` and `critical_threshold` are configured explicitly; the warning threshold remains the native battery warning setting. Low/critical colors take priority over charging green; the charging bolt uses the same alert color at low charge so it remains visible over the unfilled portion of the body. The local option changes horizontal bars; default and vertical rendering remain native. Both the old `glyph` path and the native Graphic label embedded inside the filled body were ambiguous at this size. The standalone XKB `keyboard_layout` component has been removed: its SNI tooltip fallback names the input method but cannot reliably express Rime's internal Chinese/English submode. The tray now sits in the visible system group with `drawer=true` and `pinned=["fcitx"]`; shared support enables `ClassicUI.PreferTextIcon=True` so Fcitx's native SNI image reflects its engine submode label, and other tray apps remain in the drawer. Real Rime toggles still require session acceptance; no polling daemon or simulated keys were added. Layout labels remain native English even in the `zh-CN` plugin translation.

phinger-cursors-light 32 is already the shared pointer default. At output scale 1.5 this corresponds to a nominal 48 device pixels. Mango consumes that palette directly; shared support mirrors HM's `XCURSOR_THEME`/`XCURSOR_SIZE` into the user manager and the compositor's safe environment. GTK and Xresources keep their existing sole declaration, Qt/Kitty inherit the same Xcursor environment, and Xorg sources HM session variables. No Hyprcursor configuration is needed.

## R33 notification clearance

The `hud-overlay-clearance.patch` coordinates only structured SYSTEM bar tooltips and top-right notifications. Tooltip geometry is published in output-local logical coordinates after compositor configuration; normal fade-out retains the reservation until popup destruction. Top-right notification surfaces use `exclusiveZone=-1`, so their 64 px top offset is measured from the output edge rather than a workspace already reduced by the bar. Other notification positions keep upstream workspace-relative placement.

When the default notification column overlaps SYSTEM on the same output, its complete layer surface moves below the tooltip; on short outputs it moves left. Top and bottom margins change by opposite amounts, preserving the canvas height and existing notification timers/actions/reply state. Actual per-output card heights, including exiting cards, determine clearance. When neither layout fits, SYSTEM is suppressed for the current hover; leaving the widget allows it again. Notifications under the pointer stay fixed. No periodic polling or extra service is added, and user data and notification history are unchanged.

## R34 overlay surfaces

Notification cards and OSD use `background_opacity = 1.0`, matching the solid
Noctalia panel surfaces. This keeps text and controls readable over detailed
wallpapers and prevents the small translucent fringe left by the previous 0.98
setting. Notification placement, actions, timeout, and the R33 SYSTEM clearance
behavior are unchanged.

Round 37 enables upstream `wallpaper.automation.pause_on_fullscreen` so the daily wallpaper rotation waits during fullscreen games/video. The Noctalia pin also brings notification-history encryption and lockscreen signal validation; those runtime migrations belong to Noctalia. Local source patches retain their build-time marker checks, with compatibility changes documented in the execution report. No bar layout redesign is part of this round.
