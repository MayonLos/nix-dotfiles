# TUI 统一与精简（r55–r57，2026-10-30 至 31）

现行结论见 [tools.md](../tools.md)。这里记录过程和取舍。

## 用户要求与决定

- 起因：“做的 tui 很多都没有做好，比如搜索等等”，随后“全部大改，可以推翻，哪些没必要可以删除”。
- 提过四版设计稿，包括 7 合 1 的 `mayon` 应用、yazi 式三栏和 lazygit 式手风琴。用户最后选择不合并成一个应用，只把不常用的合并进工具箱，常用的单独保留，界面在现有结构上优化。
- 删除依据：seek、power-mayon 配置从未建立，study 词库仅 1 次复习且课表为空，mcsrv 没有实例，shots 用户判断不需要。bilitui 进入过删除清单，因用户实际打开使用而恢复。
- 不重写 musicfox：只占约 35 MB，网易云没有公开接口，维护协议的成本和账号风险不值得。

## 根因记录

| 现象 | 根因 |
|---|---|
| B 站扫码报“未返回有效二维码” | 接口改为返回 `account.bilibili.com`，代码只接受 `passport.bilibili.com` |
| 语音开关交替触发 | Mango 对按住的绑定做重复（repeat_delay 400 ms）；静音识别很快结束，下一次重复又能开始。改 `bindr` 加 500 ms 防抖。修复后用户实机确认正常 |
| 语音通知堆叠 | `-t 0` 永不过期且未复用 ID。改 `notify-send -r` |
| 通知卡片发灰、有斑块 | 通知层开了模糊且底色半透明，背后内容透出。改 `no_blur:1` 和不透明底 |
| nvim 退出报 E444 | 只剩大纲窗口时 reconcile 关闭最后一个窗口。`ZZ`、`:bd\|q` 在旧版可复现，新版不再出现 |
| keys 搜 `duan` 匹配 98/157 | 子序列匹配作用于拼音全拼和长动作文本。去掉全拼子序列，并优先真实命中，降到 3 条 |

## 过程教训

- 第一次 nvim 验证用 `:q` 在旧版也不报错，说明没有复现，不能算证据；换成多种退出方式后才成立。
- Codex 自述和 dsh 状态文件都有与事实不符之处（如“截图已产”），要以实际文件和运行结果为准。
- 补全测试 `completion_ui.lua:31` 只等 250 ms，高负载时会偶发失败，空闲重跑通过。
