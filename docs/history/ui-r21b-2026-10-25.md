## builtin 运行时回归修复

主代理应用 c9b19a1 后发现 08:53:29 日志中 GTK3/GTK4/Qt builtin 渲染失败，真实输出仍停留在00:42。前述截图验证的是手工渲染的正式模板内容，**没有验证 TemplateApplyService 的真实上下文**；原 check 额外传入 custom colors，掩盖了此缺陷。此前“构建通过”和“截图一致”只在对应离线上下文成立，不能作为方案已在真实会话生效的证据。

锁定 `/nix/store/0k6cwl09arhpjvg50lfnr12xcdfhb0w4-source` 的证据：

- `src/theme/template_apply_service.cpp:384-393` 为 builtin 创建独立 `makeThemeData(request.palette)` engine，仅处理 builtin.toml；没有叠入主配置 custom colors。
- 同文件78-99行仅把 custom colors 放入 `buildUserTemplateRoot`，439-447行才交给另一个 engine 处理。`src/theme/template_engine.cpp:1488-1494` 的 `processConfigTable` 才调用 `applyCustomColors`；650-669行在 render errors 存在时拒绝写出。因此 builtin 中 `colors.onedark_*_value` 未定义，Firefox user 模板却成功。
- `src/config/config_types.h:1810-1826` 的 user schema 无 `undo_hook`；原 builtin catalog139-153/196-199行有 GTK/Qt undo hooks。因此没有把 GTK/Qt 改成 user 条目。

修法：`session-support/resources.nix` 在构建 asset bundle 时，把三个 GTK/Qt 资源里的源色表达式及 font family 解析成共享 palette 字面量。Noctalia 继续独占四个运行时输出（GTK3、GTK4、qt5ct、qt6ct），builtin IDs、catalog、import/apply/undo hooks 和 GTK extension 生命周期不变。HM 不直接声明这些运行时文件；Firefox 和其他 user 模板继续走原 user 引擎。没有改锁定上游包、启动或重启服务、接入用户会话、sudo/rebuild、stage/commit。

新增 `noctalia-template-runtime`：锁定 Noctalia 的 `theme --config` 在 Nix sandbox、独立 HOME/XDG、无 DISPLAY/Wayland/session bus 下实际写文件及运行 hooks。检查从生产 builtin.toml 投影真实 enabled IDs（CLI 没有 ID 过滤 flag），保留原路径和 hooks，**不向 builtin engine 注入 custom colors**；预置四个陈旧文件后断言全部更新且含 bg/blue/selection 原色。按 service 的前置步骤准备 GTK extension 索引，两个 GTK import hooks 必须保留手写 CSS 并接入输出。user 根来自最终 HM settings 的全部 enabled user 条目和 custom colors；真实 Firefox profile 与注册 Obsidian vault 使动态输出及 hooks 实际执行，另验证 Zathura 输出。每项必须有输出 fixture，未来新增条目若未补 fixture 会失败。重复 apply 的成功日志仍须没有 template error；原 builtin undo 脚本必须删掉四个 managed palette 和 import，同时保留原用户 CSS。

四输出负对照使用仍含 custom 表达式的原始资源、无 custom colors 的独立 engine：必须失败并保持全部旧文件不变。`gtk-qt-theme` 改为解析该应用流程的真实输出，取消会掩盖此缺陷的手工 custom-colors 渲染。
