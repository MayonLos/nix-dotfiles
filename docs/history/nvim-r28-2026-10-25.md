## 1. 运行时错误

用户的 `attempt to yield across C-call boundary` 已在基线包确定性复现，完整栈见 `.work/r28-nvim/yield-before.log`。直接触发路径是 `Space Space` 的 All：它把 files/buffers/recent 与 `lsp_workspace_symbols` 合并。先前文件源在 finder 协程内建立了 yielder，后续 LSP 响应通过 Neovim 0.12 `Client:request` 的主循环回调调用 finder；当 100 项/1ms 的让出条件成立，就从 C 回调边界调用了 `coroutine.yield()`。单独的 LSP picker 不一定触发，所以普通小文件冒烟会漏掉它。`Space ss/sS`、references、definitions 和 call hierarchy 共用相应源码路径。

锁定 Snacks 为 `2.31.0-unstable-2026-03-21`。检查当前上游 requester 后，没有找到可以只改公开调用参数的修复。新增 `patches/snacks-lsp-coroutine.patch`：LSP 回调仍在主循环转换 location/symbol（转换涉及 Neovim API），收集结果，待 `request:wait()` 恢复 finder 协程后再交付。修复 keyed request 表原先错误使用 `#`/`table.remove` 导致取消失效，并阻止已取消任务的排队请求继续发出。没有改 flake.lock 或另建 nixpkgs 实例。

`tests/picker_lsp.lua` 使用真实 Neovim Client 和本地内存 LSP transport，每种返回 250 项，强制经过让出预算，覆盖九种 files+LSP 混合源、关闭取消和迟到回复。补丁应用和运行回归都纳入 Nix check。代价：同一 finder 等匹配 clients 完成后才 drain；多 client 中有慢服务时，第一批结果可能比流式交付晚。后续 Snacks 升级应重新评估并删除已被上游替代的补丁。

新 `runtime_smoke.lua` 通过真实 Client 回调执行配置键位：gd 实际跳转、K hover、gK signature、rename workspace edit、code action 选择后编辑、diagnostic float 和 quickfix；检查 `v:errmsg`、`:messages` 与 ERROR/deprecated 通知。fixture 用 `.txt` 防止语言服务器提前自动启动。另对 files、grep、buffers、recent、git_log/status/branches/diff、diagnostics/buffer、qflist/loclist、help、keymaps、commands、command/search history、notifications、projects 共 19 类 picker 做了独立运行检查，均无错误/弃用警告，日志 `picker-smoke.log`。

## 4. 性能

最终包启动与运行测量见下文复测表。运行测量包含2.2MB/22000行大文件冷buffer打开、插入+redraw CPU路径以及本地 LuaLS hover/completion 的 request_sync 时间；不把它们宣称为 key-to-photon 或完整 LSP workspace 索引时间。
