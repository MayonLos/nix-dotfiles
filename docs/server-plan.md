# 未来服务器规划

状态：架构与实施规则已设计；没有真实服务器资料，不创建可部署的虚构主机，不安装、分区或远程执行。未来机器沿用 [Den 架构](architecture-design.md)，当前笔记本迁移不以购买服务器为前提。

## 固定的边界

| 对象 | 设计 |
|---|---|
| 平台 | 每台真实主机显式给出 `system`；初步面向 x86_64-linux / aarch64-linux 的 NixOS。新增平台要逐功能验证，当前只验证过 x86_64 |
| 复用 | 复用 aspect、模块逻辑、配方和项目 flake；不同架构不共享同一可执行文件，不把原生构建当成自动交叉编译 |
| 库存 | 只有真实主机进入 inventory；硬件事实、网络/存储实例、账号绑定与服务选择分别明确 |
| 人类账号 | `mayon` 的身份可复用；UID、home、sudo、SSH key、功能选择按主机绑定，不复制笔记本 extraGroups |
| 服务账号 | daemon 自己的账号与 StateDirectory 等归服务功能；不借 mayon 的 home、登录状态、密钥或 linger 运行生产服务 |
| 无头环境 | 不选择 interactive-session、显示管理器、Noctalia、桌面 IME、音频或 GUI；可选 CLI/编辑/语言支持 |
| 系统基础 | stable 优先、锁输入、SSH、网络、防火墙、时间同步、日志、磁盘告警、备份与恢复按实际需求配置 |
| 项目 | 编译环境仍归项目 flake；长期服务的运行环境归该服务的部署定义，不能依赖某人 `cd` 进入目录后的 direnv |

用途组合用普通 Den `includes`。`remote-workspace` 是人类 CLI 组合，系统维护与业务服务是 host 选择；不能为了得到 SSH 就把个人全套开发工具和默认浏览器带进服务器。服务模块直接消费稳定 NixOS 选项，不再包一套万能部署语言。

## 第一次添加真实机器

只在机器确定后填写以下实例表；未填项不阻塞当前笔记本重构，但阻止对应服务器部署。

| 必需事实 | 需要记录的内容 |
|---|---|
| 机器及恢复入口 | 物理机/云/VPS，架构、RAM、磁盘、是否有串口/IPMI/供应商控制台 |
| 启动与磁盘 | BIOS/UEFI，真实设备标识、分区/文件系统、加密、解锁与恢复方式；现有数据是否保留 |
| 网络 | 网卡、DHCP/静态地址、IPv4/IPv6、公网/内网、DNS、管理来源与服务公开范围 |
| 管理身份 | 人类公钥、管理员授权、host fingerprint 的可信核对方式、独立恢复凭证 |
| 业务 | 跑什么服务、域名/端口、数据路径、依赖、升级窗口、可接受停机 |
| 数据保护 | 备份目标与权限、容量、保留周期、恢复时间/丢失窗口、异地恢复密钥持有人 |
| 构建能力 | 目标能否原生构建、缓存可达性、是否有相同架构 builder；不能假定笔记本能原生构建 ARM |

库存只保存允许进入 Git/store 的事实和公钥。IP/域名若用户视为私密，也按实例秘密策略处理，不能机械要求公开；私钥、API token、备份密码均走 sops 运行时文件。

## 功能边界和服务生命周期

先复用现有 command-line、Neovim、语言和 remote-access 的合适部分；只有实际加入服务器业务时，才建立其完整功能目录。每个服务拥有软件、配置 renderer、Unix 账号、状态目录、端口及防火墙选择、运行时凭证、启动/停止/升级方式、备份导出、恢复说明和专项检查。

默认优先 NixOS 原生服务模块。只有业务明确依赖 OCI 镜像或需要该交付方式时使用容器，不把桌面 Docker 自动变成服务器必备基础设施。Docker daemon 权限是高权限边界；不自动把所有管理员放入 docker 组。Kubernetes、Nomad、服务发现、反向代理、VPN 均等真实需求出现再引入。

网络在线依赖按服务实际需要声明。SSH、日志等不依赖图形用户登录；短期构建/清理用 oneshot/timer，网络 daemon 常驻或 socket 激活要依据实际协议支持。工作目录和环境全部显式，启动不能依赖笔记本 `localhost:7897` Clash 代理。服务资源与重启规则见 [后台策略](service-policy.md)。

## 远程访问与秘密

基础设计采用非 root 人类 SSH 公钥登录，sudo 权限在该机明确授予；凭证配置、管理网络和备用入口验证成功后才关闭替代登录方式。现有笔记本 [SSH 模块](../modules/system/services/openssh.nix) 是 socket 激活、不开防火墙、未配置授权 key 的状态，不能原样复制后声称远程可用。

端口只对实际网络范围开放，同时检查 IPv4/IPv6；不要靠 SSH 改端口代替认证或防火墙。公网暴露、VPN 内网和跳板机是后续实例选择，首台服务器未知时不预选一个联网产品。SSH host key 由该机生成，换机/重装应核验指纹并有意识处理 known_hosts。

每台机器独立 sops 解密授权。当前笔记本使用 SSH host ed25519 key 作为 age 来源；服务器可以沿用该机制，但必须处理首次安装时 host key、加密 recipient 与首次秘密部署的先后关系。只把该机需要的秘密授权给它，业务服务通过运行时文件/支持的 systemd credentials 读取，不继承人类 shell 环境。备份密码及解密恢复材料必须有独立的离机恢复副本；不可只存在被备份机器本身。依据 [sops-nix 部署文档](https://github.com/Mic92/sops-nix#deploying-secrets)。

## 存储、备份和恢复

当前不选文件系统、不生成 disko 分区方案、不启用全盘擦除或 impermanence。单盘 VPS、NAS 和加密物理机的约束不同；首次实际安装再形成可审查的分区表与迁移说明。普通服务使用原生 StateDirectory/明确 `/var/lib/<service>` 等路径，不把所有应用混到一个共享可写目录；需要持久卷时逐个声明所有者和权限。

备份方案的默认候选是 **NixOS restic 定时任务**，理由是可按路径/目标集成；这只是规划选型，尚未安装或运行。锁定 nixpkgs 已有 `services.restic.backups` 模块。后端、容量和保留值必须随实例填写，不凭空设置删快照周期。restic 支持快照备份与恢复；参见 [官方备份](https://restic.readthedocs.io/en/stable/040_backup.html) 和 [恢复](https://restic.readthedocs.io/en/stable/050_restore.html) 文档。

| 数据 | 备份/恢复要求 |
|---|---|
| 配置与输入锁 | Git 可重建，但加密文件和离线恢复材料必须确实可取回 |
| 文档/上传文件/业务对象 | 独立备份到另一故障域；不能把同机快照当完整备份 |
| 数据库 | 使用数据库支持的导出/一致性备份流程；不宣称拷贝运行中的数据目录即可恢复 |
| 容器与 VM | 明确卷/磁盘和一致性策略；镜像可重拉不等于持久数据已保护 |
| `/nix/store`、cache、可重下模型 | 默认不备份；若离线恢复需要，单独说明缓存保存策略 |
| 机器身份与恢复材料 | 加密离机存放，记录恢复顺序；不进入公共 cache/store |

备份任务失败要可见，定期 check，至少在首次上线前向独立临时目标恢复一次并验证应用数据。恢复演练不写回生产路径；保留策略中的 forget/prune 只有在恢复验证、目标和保留规则确定后启用。Nix generation 回滚只回滚配置/程序，不会回滚数据库 schema、文件内容、外部 API 或秘密轮换。

## 构建、部署与回退

首台服务器先使用 NixOS 自带 `nixos-rebuild` 与 SSH，保留 Git commit + lock + generation 对应记录；暂不增加多机编排框架。当前锁定的 nixos-rebuild-ng 有 `--target-host` 和 `--build-host`，但实际账号、权限和架构确定后才写具体部署命令。多个目标确有批次/健康检查/自动回退需求时再审部署工具，不因采用 Den 就把某个 deploy 工具当必选依赖。

部署步骤固定为：审查实例差异 → 求值与目标架构构建 → 验证备份与控制台 → 传输 closure → 应用临时配置并测服务/新 SSH 会话 → 确认后持久切换 → 检查重启恢复。`nixos-rebuild test` 也会即时改变运行系统，只是不设成默认启动配置；不能把它当只读验证。网络/SSH/启动相关修改须保留原 SSH 会话，并从第二连接验证新配置；没有第二连接和恢复入口时不冒险变更这些设置。

失败先恢复已知 generation 与网络/服务可达性；涉及数据库迁移时按该服务恢复程序处理，不能以 `--rollback` 替代数据恢复。备份、旧 generation 和恢复控制台确认前不运行激进 GC。以上行为依据 [NixOS 配置变更手册](https://nixos.org/manual/nixos/stable/#sec-changing-config) 和 [锁定 nixos-rebuild 手册](https://github.com/NixOS/nixpkgs/blob/7993f34ee47e28a3d607a525aadc6c94b73be728/pkgs/by-name/ni/nixos-rebuild-ng/nixos-rebuild.8.scd)。

## 当前应完成的服务器准备

当前重构只做：平台参数不再由一个全局 x86_64 常量隐式控制所有 host；身份与绑定分离；CLI/编辑/语言可无桌面选择；秘密与服务状态边界明确；笔记本代理/电源/GPU/输入组等不向服务器泄漏；checks 检查无头组合没有 GUI、无未授权账号/开放端口。ARM 只能报告到实际完成的求值/构建层级。

新服务器出现后才做：加入真实 inventory、磁盘与网络设计、业务选择、远程授权、备份目标、构建/部署路径及实机恢复验收。相关测试可使用内部 fixture，不能导出假的服务器供人误部署。

本文已核对当前主机、SSH、Nix 代理、账号与秘密接线及上游文档；没有做服务器构建、部署、备份恢复或跨架构运行验证。
